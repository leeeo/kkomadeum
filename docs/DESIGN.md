# 꼬마듬 Increment 1 설계

기준일: 2026-10-23, 이름 갱신 2026-11-11. 개인 참가 프로젝트이며 회사 코드·계정·인프라를 사용하지 않는다.
원본: 「현대차그룹 차량용 앱 공모전 기획서 초안 v0.1」의 A·C·D와 시나리오 1.
이 문서는 원본 기획서를 바꾸지 않고 이번 구현 범위를 구체화한다.
제출 이름은 **꼬마듬 — 아이와 타는 날의 돌봄 알림**이다(2026-11-11 확정).
초기 가칭은 9류 선행상표가 확인되어 사용하지 않는다.
저장소 내부 이름·패키지 ID(`app.leeeo.gachita`)는 빌드 호환을 위해 유지한다.

## 구현 범위와 원본 대응

| 원본 | 이번 흐름 | 구현 | 실제 / 모의 |
|---|---|---|---|
| A 탑승 점검 | 주차 상태에서 아이 동승 시작 → 좌석·벨트 확인 → 출발 | 미확인은 통과하지 않음. 벨트 체결 뒤 모의 출발 활성화 | 상태 규칙 실제, 모든 차량 신호 모의 |
| B 이동 중 돌봄 일부 | 주행 중 벨트 해제·센서 미확인 경고 | 운전자 화면 입력 제거, 경고 문장 표시 및 Android TTS | 규칙 실제, 벨트 입력 모의. STT·LLM·창밖 미션 제외 |
| C 하차 준비 | ETA 10분 / 3분 임계값 | 각 안내를 세션당 한 번 발화. 3분 이하로 처음 진입하면 3분 안내만 발화 | 규칙 실제, ETA와 준비물(물병·담요)은 모의 고정값 |
| D 뒷좌석 재확인 | 시동 OFF 또는 주차+운전석 문 열림 → 확인 → 30초 미확인 강화 | 경고 지속, 보호자 알림 단계 표시, 뒷문+빈 좌석+직접 확인 후 완료 | 경고 실제, 문·좌석·시동 모의, 휴대폰 전송 없음 |
| E 가족 이동 기록 | 이번 범위 밖 | 지도·계정·백엔드·위치 저장 없음 | 미구현 |

자동 착석 감지는 아이와 짐을 구분하지 못한다. 이번에는 사용자가 주차 상태에서 아이 동승을 명시한다.
카시트의 자체 하네스 체결은 차량 안전벨트 센서와 다른 정보다. 차량 벨트가 체결되어도 카시트 안전 점검을 대신하지 않는다.
원본의 자동 해제보다 보수적으로 **직접 하차 확인 버튼**을 마지막 단계에 두었다.
도어 개방만으로 아이가 내렸다고 추정하지 않으며, 좌석 미확인을 빈 좌석으로 취급하지 않는다.

## 모듈 경계

- `domain`: Android 의존성 없는 Kotlin/JVM. 불변 `RideSession`이 모든 전이와 알림 판단을 담당한다.
- `SeatSensorSource`: 좌석 및 관련 센서 스냅샷 입력 경계. 세션에는 `SimulatedSeatSensorSource`를 사용한다.
- `app`: Compose Activity, 한국어 화면, Android TTS, 개발용 센서 패널과 Pleos 진단 버튼.
- `PleosSeatSensorSource`: 공개 `Vehicle:2.3.2`로 후석 좌측 점유·벨트의 Capability와 현재값을 1회 읽는다.
  읽기 가능 영역인지 확인하고 null/미지원은 미확인으로 매핑한다. 5초 응답 제한 후 `release()`한다.
- SDK 진단 결과는 모의 세션과 섞지 않고 별도 표시한다. 실차 신호처럼 보이는 혼합 시연을 피하며,
  조회 성공도 지속 구독·신호 신선도를 보장하지 않으므로 실제 세션 연결은 다음 단계다.
- 앱은 Pleos 좌석 읽기 권한만 요청한다. 제어 API·가족 전송·위치 API를 호출하지 않는다.

## 세션과 시간

`IDLE → CHECKING → RIDING → ARRIVAL → COMPLETE`

- 주차가 확인되어야 세션을 시작한다. 실제 주행 신호가 들어오면 점검 미완료여도 RIDING으로 추적하고 경고한다. 앱이 차량 출발을 제어하지 않는다.
- RIDING 중 단순 주차만으로 도착 판정하지 않는다. 시동 OFF 또는 주차+운전석 문 개방이 추가로 필요하다.
- ARRIVAL에서 뒤늦게 다른 센서가 들어와도 도착 시각을 덮어쓰지 않는다.
- 도착 이후 뒷문 개방 사실을 유지한다. 도착 전 개방 기록은 하차 증거로 재사용하지 않는다.
- 30초는 데모 정책값이며 안전 검증된 임계값이 아니다. `tick(nowSeconds)`가 시간 입력을 받으므로 테스트는 실제 대기 없이 정확한 경계값을 검사한다.
- 화면의 `+30초`는 가상 시계만 전진시킨다. 전경에서는 1초 간격으로 데모 시계도 진행한다.
- 강화 상태는 센서가 바뀌어도 직접 하차 확인까지 유지된다. 화면이 사라지거나 차량 전원이 꺼진 동안의 실행을 보장하지 않는다.
- Activity 재생성 시 `rememberSaveable`이 세션과 알림 플래그를 복원한다. 강제 종료·작업 제거 후 영구 복구, 프로세스가 없는 동안의 시간 추적, 백그라운드 알림은 이번 범위 밖이다.

## 주행 UI와 배포 경계

Compose는 정차 상태의 프로토타입 Activity용이다. 개발용 시뮬레이터 버튼은 운전자용 실차 UI가 아니다.
`distractionOptimized` 메타데이터를 선언하지 않았으며 주행 중 앱 실행 허용을 주장하지 않는다.
실차·앱 마켓 적용 전에 차량 UX 제한, 제3자 권한, 지원 카테고리, 전원 OFF 이후 실행 수명을 확인해야 한다.
차량이 앱을 정지시키면 현재 구현의 TTS·타이머도 동작하지 않을 수 있다.
따라서 이 APK는 시연용이며 차량 기본 후석 승객 알림 장치의 대체품으로 제공하지 않는다.

## 테스트에서 보장하는 것

미확인 입력, 시작 조건, 주행 중 벨트 변화, ETA 중복 억제, 짧은 경로, 시동/문 도착 조건,
도착 전 문 개방 배제, 29/30초 강화 경계, 빈 좌석·뒷문·수동 확인 조합, 재시작 초기화,
역행 시간·음수 ETA 거부를 검증한다. 실제 차량 권한이나 센서 정확도는 이 테스트의 보장 범위가 아니다.
